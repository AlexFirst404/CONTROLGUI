# CONTROLGUI Remote — центральный сервер (control plane)

Панель управления всеми удалёнными серверами CONTROLGUI. Node.js без npm-зависимостей,
HTTPS на самоподписанном сертификате.

## Что это
- `https://IP/` — главная: регистрация (ник + пароль, с одобрением админа), вход,
  привязка своего сервера по коду, список доступных серверов со Старт/Стоп/Рестарт.
- `https://IP/admin` — админка: заявки на регистрацию, все серверы, назначение серверов
  пользователям, управление пользователями.
- `/agent/*` — туннель для локальных панелей: они держат исходящий SSE-поток и выполняют
  команды из белого списка (`start | stop | restart`). Произвольный код не передаётся.

## Архитектура туннеля (за NAT, без проброса портов)
Локальная панель → POST `/agent/register` (panelToken) → получает `globalId` + `linkCode`.
Панель открывает SSE `/agent/stream?token=…`; центр шлёт команды событиями; панель
выполняет и постит результат на `/agent/result`. Статус — push на `/agent/status`.

## Деплой
```sh
scp -r central root@IP:/opt/controlgui-remote
ssh root@IP 'bash /opt/controlgui-remote/deploy/setup.sh'
```
Скрипт ставит Node, генерирует серт на IP, заводит systemd-сервис на :443, открывает
firewall. Пароль первого админа — в `data/ADMIN-CREDENTIALS.txt`.

## Данные
JSON в `data/` (атомарная запись tmp+rename): `accounts.json`, `servers.json`.
Серт в `cert/` — оба каталога в `.gitignore` (генерируются на сервере).

## Переменные окружения
- `PORT` (по умолч. 443; для локального теста 8443)
- `CGR_DATA` — каталог данных
- `CGR_CERT` / `CGR_KEY` — пути к серту
- `CGR_ADMIN` — логин первого админа (по умолч. `admin`)
