# CONTROLGUI Remote — центральный сервер + удалённое управление (дизайн)

Дата: 2026-06-27. Статус: на согласовании.

## Контекст и цель
Локальные панели CONTROLGUI работают на домашних машинах пользователей (за NAT,
без белого IP). Нужен **центральный сервер «CONTROLGUI Remote»** на выделенном
VPS (89.125.169.61), который позволяет:
- главному **админу** видеть и удалённо управлять **всеми** подключёнными серверами;
- **пользователям** регистрироваться (с одобрением админа) и либо владеть серверами,
  которые они привязали, либо получать серверы, назначенные админом/владельцем;
- включать на конкретном сервере в локальной панели тоггл **«Удалённое управление»**,
  который связывает этот сервер с центральным сервером.

## Декомпозиция
- **A. Фиксы macOS** (независимые, мелкие).
- **B. Центральный сервер** (новое приложение, папка `central/`, отдельная ветка).
- **C. Клиент удалённого управления в панели** (тоггл + туннель).
- **D. Деплой на VPS.**

Сборка — **всё сразу** после одобрения спеки.

## A. Фиксы macOS
1. **Курсор слишком большой на Mac.** Общий `cursor.png` = ×3 (36×54); macOS рисует
   курсор в его пиксельном размере (без даунскейла как на Windows), отсюда «огромный».
   Фикс: отдать курсор подходящего размера (целевой ~24px) и/или учитывать DPR; при
   необходимости — платформо-зависимый размер. (Согласуем итоговый размер визуально.)
2. **Курсор сбрасывается при прокрутке колёсиком.** WebKit иногда теряет CSS-курсор на
   wheel-событиях. Митигация: переустанавливать курсор (например, на `wheel`/`scroll`
   переустановить класс/стиль) и/или более устойчивое правило.
3. **Нативное окно приложения на Mac** (сейчас всегда браузер). Делаем маленькое
   **Swift-приложение с WKWebView**, компилируется в CI (`swiftc` есть на macOS-раннере),
   кладётся в `.app`; лаунчер запускает его (иначе — браузер). Без рантайм-зависимостей
   (python+WebKit на Mac потребовал бы PyObjC, который не идёт из коробки — потому Swift).

## B. Центральный сервер (`central/`, Node, без npm-зависимостей)
- **HTTPS напрямую**: самоподписанный сертификат (через `openssl`), Node слушает 443
  (веб-UI + туннель агентов). Caddy не нужен (домена нет — самоподпись).
- **Веб-UI** (бренд «CONTROLGUI Remote», тема Minecraft/Ore-UI как у панели):
  - `/` — главная: регистрация (ник + пароль, **с одобрением админа**), вход. Вошедший
    видит доступные ему серверы (свои + назначенные) или «нет доступных серверов».
  - `/admin` — админ-панель (только админ): все серверы и панели, заявки на регистрацию,
    назначение серверов пользователям с правами.
- **Туннель** (без WebSocket-библиотеки, на встроенном Node):
  - агент (локальная панель) держит **SSE** `GET /agent/stream?token=…` — центр пушит
    команды событиями;
  - агент шлёт `POST /agent/register` (привязка), `POST /agent/status` (статус),
    `POST /agent/result` (результат команды по reqId).
  - Команды строго из **белого списка**: `status | start | stop | restart`. Никакого
    произвольного выполнения по туннелю.
- **Данные** (JSON-файлы, как в панели):
  - `accounts.json`: `{username, hash, salt, role: admin|user, approved, createdAt}`.
  - `servers.json`: `{globalId, ownerAccount, name, status, lastSeen, panelToken,
    access:[{username, perms}]}`.
  - коды привязки: `{code -> globalId, expires}` (одноразовые).
- **Переиспользуем** из `lib/users.js` панели: pbkdf2-хэш, сессии-куки, анти-брутфорс
  входа, набор ключей прав (`PERM_KEYS`).

## C. Клиент в локальной панели (`lib/` + `public/`)
- Тоггл **«Удалённое управление»** — **на сервер**, почти в самом верху настроек сервера.
- При включении: панель шлёт `POST https://89.125.169.61/agent/register` (адрес **вшит**
  в сборку; самоподписанный серт **запинен** в панели) с сгенерированным `panelToken` и
  метаданными сервера → центр возвращает `globalId` и **одноразовый код привязки**,
  панель показывает код пользователю. Панель открывает SSE-туннель, шлёт статус, слушает
  команды (белый список). Сохраняет тоггл+token+globalId; переподключается при старте.
- При выключении: панель уведомляет центр, закрывает туннель, сервер убирается.

## Потоки
- **Включение тоггла** → сервер сразу появляется у **админа** (без владельца). Панель
  показывает код.
- **Привязка**: пользователь (одобренный аккаунт) вводит код на `/` → становится
  **владельцем** (в MVP полный контроль = статус + старт/стоп/рестарт).
- **Раздача доступа**: **владелец ИЛИ админ** дают другим пользователям доступ к серверу
  с выбранными правами (назначенный доступ ограничен выданными правами).

## Безопасность
- Самоподписанный HTTPS (трафик шифруется; браузер покажет «не безопасно» — принято;
  бесплатный домен (DuckDNS и т.п.) убрал бы предупреждение — предлагаю на будущее).
- `panelToken` на сервер; сгенерированный аккаунт админа; регистрация с одобрением;
  анти-брутфорс входа; **белый список команд** (нет произвольного выполнения).
- Центральный VPS — высокодоверенный (его компрометация = доступ к управлению
  подключёнными MC-серверами). Для MVP принимаем; на будущее — доп. харднинг.
- **Рекомендация: сменить root-пароль SSH после деплоя** (он засветился в чате).

## D. Деплой (89.125.169.61, чистый Linux)
- Установить Node (LTS), сгенерировать самоподписанный серт (`openssl`), выложить
  `central/`, systemd-сервис (автозапуск), фаервол (открыть 443 и ssh).
- Создать аккаунт админа (сгенерированные логин+пароль → выдать тебе).

## Фазы
- **MVP (этот заход):** всё выше, удалённые действия = статус + старт/стоп/рестарт.
- **Фаза 2:** удалённая консоль (мост SSE), файлы, полные настройки.

## Проверка (что тебе нужно будет проверить)
1. Открыть `https://89.125.169.61/` (принять предупреждение самоподписи), зарегистрировать
   юзера (висит в заявках), одобрить его из админки.
2. В локальной панели включить «Удалённое управление» на сервере → показан код.
3. Ввести код на сайте → сервер появился как твой; старт/стоп/рестарт работают удалённо;
   админ видит все серверы и может назначать.
4. macOS: курсор нормального размера, не сбрасывается при прокрутке, открывается нативным окном.
