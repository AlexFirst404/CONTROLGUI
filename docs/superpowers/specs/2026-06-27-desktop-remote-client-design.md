# Десктоп управляет удалёнными серверами по коду (как локальными)

Дата: 2026-06-27. Статус: одобрено (подход + авторизация).

## Цель
В десктоп-панели, помимо создания/управления ЛОКАЛЬНЫМИ серверами, дать вход в аккаунт
CONTROLGUI Remote и добавление удалённого сервера ПО КОДУ; такой сервер появляется в общем
списке рядом с локальными и управляется ТЕМ ЖЕ интерфейсом (консоль/файлы/игроки/настройки…).

## Решения (от пользователя)
- Интеграция: **в общем списке, прозрачно** (не отдельная страница).
- Авторизация: **вход в аккаунт центра + добавление по коду**.

## Архитектура (Approach A — прозрачный клиент центра)
Панель (десктоп) становится клиентом центрального сервера. Управление удалённым сервером —
тройной хоп: браузер → панель-десктоп → центр `/r/<gid>/*` → туннель → удалённая панель.
Проксирование в БЭКЕНДЕ панели (server-to-server), без CORS.

### Компоненты
- **`lib/centralclient.js`** — клиент центра:
  - `state()` → {loggedIn, username, central}; хранит сессию в `data/central-account.json` (0600):
    {central, username, cookie}.
  - `login(u,p)` / `logout()` → POST центр `/api/login` (ловим Set-Cookie `cgr_sid`) / `/api/logout`.
  - `linkByCode(code)` → POST центр `/api/link {code}` (с кукой) — привязать сервер к аккаунту.
  - `listRemote()` → GET центр `/api/servers` → [{globalId,name,type,version,status,online,role,…}];
    для каждого резолвим remoteLocalId через прокси `/r/<gid>/api/servers` (кеш карты gid↔localId).
  - `proxy(gid, req, res)` — форвард в центр `/r/<gid><path>` с кукой; ретрансляция ответа (вкл.
    SSE-консоль через стриминг). TLS — пиннинг серта (как в `remote.js`).
- **Слияние списка** — `GET /api/servers` (панель) отдаёт локальные серверы + удалённые из
  `centralclient.listRemote()`, каждый с пометкой `remote:true, gid, central`. Десктоп-id удалённого =
  его remoteLocalId (резолвится); карта `remoteLocalId→{gid}` в памяти.
- **Прозрачный прокси в `handleApi`** — если целевой id — удалённый (в карте), весь запрос
  (любой под-экшен, вкл. стриминг консоли) форвардится в `centralclient.proxy(gid,…)`. Фронт почти
  не меняется (управление как локальным).
- **Новые роуты панели** — `GET /api/central` (статус), `POST /api/central/login|logout|link`.
- **UI (`app.js`)** — блок «Удалённые серверы» на главной: если не вошёл — форма входа в аккаунт
  центра; вошёл — «Привязать по коду» + удалённые серверы в списке с бейджем «удалённый».
  Кнопки, неприменимые к удалённому (удалить/создать локально), для remote-серверов скрыты
  (центр и так вернёт 403 по денилисту). Бейдж онлайн/офлайн.

## Безопасность
- Сессия центра хранится в панели server-side (0600) — это сессия самого пользователя, панель
  действует от его имени. Пиннинг серта панель→центр. Права на удалённый сервер enforce-ит центр
  (денилист + perms — уже сделано).
- Если центр офлайн / сессия истекла — удалённые серверы помечены офлайн, просим перелогиниться.

## Поток (консоль удалённого сервера в десктопе)
браузер → панель `/api/servers/<remoteLocalId>/console` → handleApi видит remote →
`centralclient` стримит из центра `/r/<gid>/api/servers/<remoteLocalId>/console` → центр → туннель →
удалённая панель → SSE назад через два прокси → браузеру.

## Ошибки / тесты
Центр офлайн → 502/офлайн-бейдж; коллизия id локального и remoteLocalId → префикс. Тест: тройной
E2E (удалённая панель ← центр ← десктоп-панель): вход в аккаунт, привязка по коду, список,
чтение файла, консоль удалённого сервера через десктоп. Адверсариальный воркфлоу-ревью перед релизом.

## Этапность
1. `lib/centralclient.js` (сессия, login/link/list/proxy + стриминг).
2. Роуты `/api/central/*` + слияние списка в `/api/servers` + прокси в `handleApi`.
3. UI: блок входа/привязки + бейдж + скрытие неприменимых кнопок.
4. Тесты (тройной E2E) → ревью → релиз.
